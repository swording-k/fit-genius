# FitGenius 动作学习与双视频对比设计

**日期：** 2026-09-19  
**状态：** 待产品确认  
**目标版本：** iOS 首版

## 1. 产品目标

FitGenius 不只向健身入门用户生成训练计划，还要让用户能够沿着计划逐个学会动作、完成训练并看到自己与标准演示的差异。

完整闭环为：

1. 获得个性化训练计划。
2. 点击计划中的某个动作。
3. 理解这个动作在计划中的做法和对应动作库条目。
4. 通过谭成义（谭 sir）的短教学片段学习。
5. 按照参考视频的机位和构图拍摄自己。
6. 同屏、同步播放两段视频，由用户直观对比。
7. 对现有姿态分析支持的动作，继续可选进入 FitGenius 的本地动作分析。

该功能服务于“帮助健身爱好者入门并坚持下去”的核心定位，不是一个独立的视频社区或通用视频剪辑工具。

## 2. 现有基础与真实缺口

工程已经具备：

- 1324 个 `ExerciseTemplate` 动作模板。
- 中英文动作名、分步说明、器械、目标肌群和动图展示。
- `ExerciseDetailView` 动作库详情页。
- AI 计划生成后按名称回连 `ExerciseTemplate` 的能力。
- 视频选择、AVFoundation 帧提取、视频压缩与本地姿态分析。

当前缺口是：

- 计划动作行本身不是学习入口。
- 手动添加、旧计划或名称不一致的动作可能没有回连模板。
- 动作模板没有独立的教学视频片段目录。
- 没有参考视频与用户视频的同屏播放器。

## 3. 方案比较

### 方案 A：把视频 URL 直接加到 `ExerciseTemplate`

优点是实现快。缺点是一个动作只能有一段视频，无法表达长视频中的多个动作片段，也会让内容更新与 SwiftData 迁移绑死。不采用。

### 方案 B：独立教学片段目录（推荐）

使用独立的 `ExerciseTutorialClip` 内容模型，通过 `ExerciseTemplate.externalId` 关联。一个模板可对应零个、一个或多个教学片段；一个长视频也可以切分成多条片段映射不同动作。内容可以独立更新，不改变训练计划数据。采用此方案。

### 方案 C：只跳转到外部平台

优点是开发和存储成本最低。缺点是离开 App、难以精确播放某个动作片段，也无法完成双视频对比。只作为尚未获得可播放素材时的备用入口。

## 4. 用户流程

### 4.1 从计划进入动作学习

1. 用户打开某个训练日。
2. 点击动作卡的主内容区进入详情；完成勾选和侧滑编辑、删除保持独立。
3. 详情页显示当前计划处方：组数、次数、重量和备注。
4. 如已关联动作模板，显示标准名称、动作库演示、目标肌群、分步做法和常见提示。
5. 如有经确认的谭 sir 教学片段，显示“看教学”。
6. 如无视频，不显示空播放器，详情页其他内容仍可使用。
7. 如没有匹配动作模板，仍展示计划处方与备注，并明确标记“尚未匹配标准动作”，不做错误映射。

### 4.2 观看教学片段

1. 教学页默认播放指定时间段，而不是整条原视频。
2. 显示创作者、原视频标题、原链接和来源平台。
3. 在拍摄前显示该片段的参考机位和构图截图，提示用户尽量保持一致。
4. 用户可从相册选择自己的视频进入对比。

### 4.3 双视频对比

1. 参考视频和用户视频左右并排。
2. 一个公共播放、暂停和进度控件同时驱动两个播放器。
3. 用户可分别调整参考片段和自己视频的起始点，手动对齐第一次动作开始。
4. 播放时两边使用同一个归一化进度；长度不同时，较短视频到达结尾后停在末帧。
5. 支持 0.25x、0.5x 和 1.0x 同步速度。
6. 第一版不自动判断机位是否一致，不自动对齐动作相位，不为不支持的动作生成分数。
7. 如该动作属于现有姿态分析支持集，单独提供“分析我的动作”入口；分析结果不伪装成谭 sir 的个人评价。

## 5. 数据与内容模型

### 5.1 `ExerciseTutorialClip`

教学片段使用独立的 Codable 目录模型，不作为 SwiftData 用户数据：

```swift
struct ExerciseTutorialClip: Codable, Identifiable, Hashable {
    enum RightsStatus: String, Codable {
        case developmentOnly
        case licensed
        case externalLinkOnly
    }

    let id: String
    let exerciseTemplateIDs: [String]
    let creatorName: String
    let sourcePlatform: String
    let sourceURL: URL
    let sourceVideoID: String
    let sourceTitle: String
    let clipStartSeconds: Double
    let clipEndSeconds: Double
    let playbackURL: URL?
    let posterURL: URL?
    let cameraView: String?
    let framingNoteZh: String?
    let framingNoteEn: String?
    let rightsStatus: RightsStatus
}
```

约束：

- `clipEndSeconds` 必须大于 `clipStartSeconds`。
- 同一条长视频可以产生多个 clip。
- 一个 clip 可以映射一个或多个确实同义的动作模板。
- `developmentOnly` 只能在 DEBUG 版本中播放。
- `licensed` 才能在 Release 版本中使用 `playbackURL`。
- `externalLinkOnly` 只显示原始来源链接，不在 App 内重新分发视频。

### 5.2 目录发布

- App 随包带一份已审核的 `tutorial_clips.json` 作为离线元数据和回退。
- 后续可从 CloudBase Storage 获取同 schema 的更新目录，本地验证后覆盖内置版本。
- 视频文件不放入 Git，不大量打包进 IPA。
- 授权后的正式片段使用 CloudBase Storage/CDN 播放地址。

### 5.3 动作映射

自动候选只用于减少人工工作，不直接进入产品目录。处理流程为：

1. 拉取谭 sir 公开账号的视频元数据。
2. 从标题、简介和可获得的字幕/文稿中提取动作名。
3. 使用中英文别名表与 1324 个 `ExerciseTemplate` 生成候选。
4. 人工确认动作、开始/结束时间、机位和构图。
5. 只有通过人工确认的记录才进入 `tutorial_clips.json`。

## 6. 素材工作流

### 6.1 开发期

- 建立谭 sir 公开视频清单，保存 ID、标题、链接、发布日期和可用文稿。
- 下载或缓存仅用于本地原型的素材到不入 Git 的目录。
- 用 `ffmpeg` 按审核后的时间段裁切 H.264/AAC MP4，输出标准横竖比和封面。
- 首先跑通少量确定片段，再执行批量盘点，避免在播放器和数据 schema 未稳定时大量返工。

### 6.2 正式上线

- 获得创作者对 App 内展示、剪辑、存储、分发和商业使用的明确授权。
- 优先使用创作者提供的原始视频，避免多次转码、平台水印和过期直链。
- 将授权状态从 `developmentOnly` 改为 `licensed` 前，逐条核对素材来源和授权范围。
- Release 构建不允许任何 `developmentOnly` 播放地址通过校验。

## 7. 工程分层

### 7.1 内容层

- `ExerciseTutorialClip.swift`：内容模型和权利状态。
- `ExerciseTutorialCatalog.swift`：加载内置/远程目录、schema 验证、按 template ID 查询。
- `tutorial_clips.json`：已审核映射，不包含二进制视频。

### 7.2 产品界面层

- `PlannedExerciseDetailView`：面向某个计划实例，展示处方与标准动作内容。
- `ExerciseTutorialView`：播放片段、展示来源和机位参考、选择用户视频。
- `ExerciseVideoComparisonView`：双播放器和公共时间线。
- `SynchronizedVideoController`：不依赖 SwiftUI 界面的同步播放、暂停、跳转、倍速和起点偏移逻辑。

### 7.3 素材工具层

- 视频清单拉取脚本：只生成元数据和原链接。
- 审核清单：CSV/JSON 记录动作模板 ID、片段时间和权利状态。
- 转码脚本：只处理已审核记录，不会自动将未确认素材发布到产品目录。

## 8. 错误与降级

- 无模板匹配：只显示计划处方和备注。
- 有模板、无教学片段：显示动作库图示和文字，不显示视频按钮。
- 片段无授权播放地址：只显示可用的原始来源链接。
- 网络失败：详情文字与本地 GIF 缓存仍可使用；视频区给出重试。
- 用户视频无法解码：保留参考片段，允许重新选择。
- 同步偏差：在播放、拖动和回到前台时重新 seek 两边时间，不在每帧做昂贵校正。

## 9. 测试与验收

### 自动化验证

- 目录解码、时间段校验和 rights status 过滤。
- template ID 查询和多片段排序。
- 旧计划动作的精确/别名匹配，以及歧义时拒绝自动匹配。
- 归一化时间线、双起点偏移、较短视频结尾和倍速逻辑。
- Release 构建过滤 `developmentOnly` 素材。
- 中英文本地化完整性检查。

### 交互验收

- 从今日计划点击动作可进入详情，不误触完成勾选或侧滑操作。
- 有视频的动作可播放指定片段；无视频的动作不出现空白播放器。
- 用户可选择本地视频，进入左右对比。
- 播放、暂停、拖动、起点调整和 0.25x/0.5x/1.0x 会同时作用于两个视频。
- 页面回到前台后不出现双重声音或一边独自播放。
- iPhone 真机使用一组谭 sir 参考片段和一组用户视频完成实际对比。

## 10. 分期与完成标准

### 里程碑 1：计划动作可学习

- 计划行进入动作详情。
- 标准动作库内容与计划处方同页展示。
- 旧数据与未匹配动作可安全降级。

### 里程碑 2：谭 sir 教学片段

- 目录 schema、加载器、素材盘点表和首批审核片段可用。
- 工程能够区分开发素材、已授权素材和外链素材。
- 每条片段都能追溯原始链接和动作模板。

### 里程碑 3：同机位双视频对比

- 用户可参照教学视频构图选择自己的视频。
- 左右视频可手动起点对齐、同步播放和慢放。
- 不宣称自动机位判断或自动动作对齐。

### 里程碑 4：批量内容盘点

- 盘点谭 sir 公开视频，长视频按动作分段。
- 能找到并人工确认的动作尽量全部映射。
- 少数无视频或无法确认的动作保持空缺，不使用低置信度自动映射。

## 11. 明确不在首版范围内

- 自动识别用户的摄像头角度。
- 根据角度实时指挥用户移动手机。
- 自动将两段视频对齐到相同动作相位。
- 为 1324 个动作强行配置教学视频。
- 把视觉相似度直接当作动作质量分数。
- 未获授权就在 Release 版本重新分发创作者视频。

## 12. 产品决策摘要

- 教学视频是动作详情的增强内容，不是进入详情的前置条件。
- “对应谭 sir 的每个已发布动作”通过内容盘点实现，而不是要求每个 FitGenius 动作都有视频。
- 首版对比是可控、诚实的同机位观察工具，不宣称自动专业判定。
- 内容数据、用户训练数据和视频二进制文件保持分离，以便后续更新、授权和迁移。
