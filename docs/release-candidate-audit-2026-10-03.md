# 发布候选检查（2026-10-03）

本记录区分已确认的源码缺陷、已验证的媒体交付和仍需真机验收的行为。检查不等于已修复；当前分支不合并、不提交商店审核。

## 已确认的发布问题

| 问题 | 当前证据 | 建议修复与验收 |
|---|---|---|
| 首次空计划被当成有效云数据 | `CurrentWorkoutPlanStore.ensureCurrentPlan` 自动创建零天数计划；`CloudSnapshot.hasMeaningfulData` 仅判断 plan 非 nil；Coordinator 首次同步先上传本地 | 排除自动空草稿；已有云数据优先恢复。仅明确 404 代表无远端，网络失败不可按不存在处理。覆盖空草稿恢复、手动计划保留、读取失败不写云端 |
| AI 初始生成和未登录重新生成静默返回固定计划 | `AIService.generateInitialPlan` 认证失败、解析失败及 `regeneratePlan` 认证失败调用 `fallbackPlan` | 返回明确认证/解析错误；保留现有手动计划；自有 Key 直连仍免登录。测试未登录、无效 JSON、合法四分化输出 |
| 生产账户删除缺失 | iOS 调用 DELETE `/api/account`；CloudBase 函数无该路由 | 实现认证后的用户隔离清理和网关路由；补齐本地四个健康模型。不用真实账户测试删除，用隔离测试数据/模拟库验证 |
| 大账户快照超过网关 ~100 KB | 客户端 PUT 全量 JSON；服务端已记录限制 | 单独设计经过身份校验的 Storage 或分块协议，不能仅增大函数内限制；旧协议兼容、重试幂等、账户隔离、大于100 KB往返均要验证 |
| Main / Widget / Watch 版本不一致 | 主 App 1.5.1 / 20260804，扩展 1.5 / 20260722 | 查询已上传最高 build 后统一版本；Archive 验证，不猜 App Store Connect 状态 |

## 建议的最小修复顺序

先处理空草稿云恢复和 AI 错误透明化，再补账户删除；大快照协议另列独立实现。已有媒体扩充沿用当前架构，不受此设计确认影响。实现前由所有者确认这组数据行为改动；未确认时只保留诊断记录。

## 尚未替代的验收

- 新旧真机升级数据连续性、Apple 登录和双设备云恢复。
- Photos 选片、声音、拖动进度与同屏手动比较。
- Watch 与 HealthKit 授权/同步。
- 真人素材当前均为 developmentOnly；正式播放范围需由所有者提供授权信息，不直接改标签。
- 当前隐私政策包含 CloudBase / MiniMax；隐私 manifest 与真实健康/账户数据流仍需核对。

媒体和索引云端发布成功，不代表上述缺陷已修或 App Store 已上线。
